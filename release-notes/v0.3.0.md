# v0.3.0 Release Notes

> Released: 2026-10-20
> `desktop-v0.3.0` · `@taco-ai/{protocol,shared,sidecar,cli}@0.3.0`

A release about knowing what the agent is about to do: shell approvals are decided from the parsed command instead of its text, the approvals waiting on you are visible from anywhere in the app, and provider settings — key, endpoint, model list — finally live in one place with a test that exercises the path a session really uses.

---

## English

### Features

- **Shell approvals read the parsed command, not its text** — the sidecar parses bash and PowerShell with tree-sitter before it decides, so a quoted metacharacter, a `sudo` prefix, a `find -exec`, a combined container option or a benign `git -c` no longer slips past a rule that was supposed to catch it. `commandPermissions` grows separate `allow` and `deny` lists — the old `rules` list is still read and folded into `allow` — plus `allowedDirectories` for static directory changes, and the shell grammars now ship inside the sidecar and desktop bundles — `sidecar` + `desktop`
- **Approvals waiting on you are visible from anywhere in the app** — an always-visible button lists the approvals every workspace is holding, a modal shows the command and the reason behind each one, and the sidecar denies the whole batch as soon as it knows no client can answer instead of waiting on a request that would never arrive. IM approval requests surface the same way — `desktop` + `sidecar`
- **One control per IM policy field** — the inherited value is tagged with the layer it comes from, so a single dropdown shows both what you inherited and what you are overriding; the two working-directory fields collapse into one `shared` / `per-chat` / `custom` picker — `desktop` + `sidecar`
- **Provider settings in one panel, with a connection test** — built-in and custom providers share one card and one editor, so the key, the endpoint and the model list live together instead of behind two dialogs. The new test sends one minimal chat turn through the same path a session uses, so a pass means the key, the endpoint, the protocol and the model id all work together — many relays answer `/models` while refusing chat, or the other way round. Failures are classified (auth / not found / rate limited / timeout / network) so the panel can name the fix, and a saved key can be revealed in place while staying masked by default — `desktop` + `sidecar`

### Improvements

- **Tool results are capped before they enter the session** — every tool result is now limited by size, and grep caps by bytes rather than by line count, so one verbose command can no longer push a whole conversation past the model's context window — `sidecar`
- **The harness runtime now lives in `@taco-ai/pi-harness`** — Pi 1.0 removed `AgentHarness` from `pi-agent-core` and left no stable replacement, so the harness surface moved into a package this project publishes itself. `pi-ai` moves from 0.99.2 to 1.3.0; the on-disk session format is unchanged — `sidecar`

### Fixes

- **A default model that stops resolving no longer bricks the workspace** — when the catalog moved under it (its provider was deleted, the model was dropped from a provider's list, a custom provider's list was edited), the workspace answered in two different ways depending on which path hit it: construction returned nothing, so every `session.create` failed with "no model configured" pointing at the wrong thing, while the hot-reload path kept the previous value and looked fine until the next restart. Both now fall back to the first catalog model, and deleting the default provider clears the default instead of leaving it dangling — `sidecar` + `desktop`
- **The sidecar picks itself back up when something goes wrong** — an IM channel that lost its network connection reconnects on its own instead of waiting for the app, a failed subagent now reports how far it got and whether it can be resumed, and the edit card renders from the harness's unified patch so the line numbers on it are real — `sidecar` + `desktop`

### Breaking changes

- **Wire protocol 2.1 → 2.2** — a 2.2 client refuses a 2.1 daemon at handshake instead of failing later on one particular RPC. `provider.listModels` now takes `{ providerId }`, `settings.write` carries `providerExtraModels` / `providerHiddenModels`, and `providers.revealKey` is new. A 2.1 daemon still accepts the handshake, but it drops the two model-list fields on write and rejects the new `listModels` shape — keep the desktop and the sidecar on the same release line — `sidecar` + `desktop`
- **`auto` approves more than it used to** — `auto` used to auto-pass strictly read-only commands only, and anything that could change the workspace asked first. The decision now comes from the parsed command, and what always asks is a built-in floor — privilege escape, destructive commands, external side effects. Everything else, including commands that write into the workspace, passes without a prompt in `auto` mode. If you read `auto` as "read-only only", keep `mode: "ask"` and list what you want passed in `allow` — `sidecar`
- **An IM policy file from 0.2.10 or earlier migrates to `ask`** — `auto` in an IM policy used to auto-pass only strict read-only commands (and, with an allow list, refuse everything outside it), and now allows every command outside the deny lists, so reading an old file verbatim would have silently widened it. Every `auto` layer becomes `ask` on load; an allow list keeps auto-passing, and a chat layer that inherited `auto` now inherits the migrated `ask` — `sidecar`
- **The IM policy working directory is one field** — `binding` and `perChatScratch` are replaced by `executionDir` (`shared` / `per-chat` / `custom`). The old fields are still read from existing files and are dropped once `executionDir` is written — `sidecar`

## 中文

### 新功能

- **shell 审批读的是解析后的命令，而不是它的文本** —— 服务端先用 tree-sitter 解析 bash 和 PowerShell，再决定放不放行，于是加了引号的元字符、`sudo` 前缀、`find -exec`、组合式容器选项或者一条无害的 `git -c` 都没法再从本该拦住它的规则底下钻过去。`commandPermissions` 分成 `allow` 和 `deny` 两张表 —— 旧的 `rules` 仍然会被读取并折进 `allow` —— 另外新增 `allowedDirectories` 用于静态目录切换；shell 语法文件现在随 sidecar 与桌面端一起打包 — `sidecar` + `desktop`
- **等着你点的审批，在应用任何位置都看得见** —— 一个常驻可见的按钮列出所有工作区正在等的审批，弹窗里给出每一条命令和背后的理由；当服务端确认没有任何客户端能应答时，它会一次性拒绝整批，而不是继续等一个永远不会来的回应。IM 侧的审批请求同样这样呈现 — `desktop` + `sidecar`
- **IM 渠道策略每个字段一个控件** —— 继承来的值标着是哪一层给的，于是一个下拉框既看得到继承了什么、也改得了覆盖成什么；两个工作目录字段合并成一个 `shared` / `per-chat` / `custom` 选择器 — `desktop` + `sidecar`
- **provider 设置并到一个面板，并带连通性测试** —— 内置与自定义 provider 共用一张卡片、一个编辑器，密钥、端点、模型列表因此待在一处，而不是散在两个弹窗里。新的测试会走会话真正使用的那条路径发一条最简对话，所以测通过就意味着密钥、端点、协议和模型 id 一起能用 —— 不少中转能答 `/models` 却拒绝对话，或者反过来。失败会被分类（鉴权 / 不存在 / 限流 / 超时 / 网络），面板因此能指出该改什么；已保存的密钥可以就地显示，默认仍然遮着 — `desktop` + `sidecar`

### 优化

- **工具结果在进入会话之前就被截断** —— 每一条工具结果现在都按大小封顶，grep 按字节而不是按行数封顶，于是一条啰嗦的命令再也没法把整段对话顶出模型的上下文窗口 — `sidecar`
- **harness 运行时搬到 `@taco-ai/pi-harness`** —— Pi 1.0 从 `pi-agent-core` 里删掉了 `AgentHarness` 且没有留下稳定替代，于是这层 harness 接口搬进了本项目自己发布的包里。`pi-ai` 从 0.99.2 升到 1.3.0；落盘的会话格式不变 — `sidecar`

### 修复

- **默认模型解析不到时，工作区不再瘫掉** —— 当模型目录在它脚下变了（provider 被删、模型从某个 provider 的列表里去掉、自定义 provider 的列表被改过），工作区此前会因为命中哪条路径而给出两种行为：构造时返回空，于是每次 `session.create` 都以"未配置模型"失败，指的还是错的东西；热重载路径则留着旧值，看起来一切正常，直到下次重启才炸。现在两条路径都会回落到目录里的第一个模型，删除默认 provider 也会顺手清掉默认项，而不是留一个悬空引用 — `sidecar` + `desktop`
- **出事之后 sidecar 自己能爬起来** —— 掉网的 IM 渠道会自己重连，不再等着应用来救；失败的子代理现在会报告它做到了哪一步、能不能接着跑；编辑卡片改从 harness 的统一补丁渲染，上面显示的行号因此是真的 — `sidecar` + `desktop`

### 破坏性变更

- **线路协议 2.1 → 2.2** —— 2.2 的客户端会在握手阶段直接拒绝 2.1 的 daemon，而不是等到某个具体 RPC 才失败。`provider.listModels` 改用 `{ providerId }`，`settings.write` 带上 `providerExtraModels` / `providerHiddenModels`，并新增 `providers.revealKey`。2.1 的 daemon 仍会接受握手，但会在写入时丢掉那两个模型列表字段，也拒绝新的 `listModels` 形状 —— 桌面端与 sidecar 请保持在同一条发布线上 — `sidecar` + `desktop`
- **`auto` 批准的范围比从前大** —— 过去 `auto` 只自动放行严格只读的命令，任何会改动工作区的命令都要先问一句。现在裁决来自解析后的命令，而始终需要询问的是一道内置底线：提权逃逸、破坏性命令、对外副作用。其余命令——包括会写工作区的——在 `auto` 模式下都会直接放行。如果你理解的 `auto` 是"只放只读"，请保持 `mode: "ask"`，把想放行的写进 `allow` — `sidecar`
- **0.2.10 及更早写的 IM 策略文件会迁移成 `ask`** —— IM 策略里的 `auto` 过去只自动放行严格只读的命令（带 allow 表时，表外的全部拒绝），而现在放行一切不在 deny 表里的命令，所以照原样读旧文件等于悄悄放宽。每层 `auto` 在加载时都会变成 `ask`；allow 表仍然自动放行，而原本继承 `auto` 的会话层现在继承迁移后的 `ask` — `sidecar`
- **IM 策略的工作目录合并成一个字段** —— `binding` 与 `perChatScratch` 被 `executionDir`（`shared` / `per-chat` / `custom`）取代。旧字段仍会从已有文件里读取，一旦写入 `executionDir` 就会被丢弃 — `sidecar`

## Upgrade notes

- Workspace versions advance `0.2.10 → 0.3.0` across `desktop`, `protocol`, `shared`, `sidecar`, and `cli`.
- Wire protocol advances `2.1 → 2.2`. The bump is deliberate: a 2.1 daemon answers `settings.write` with `ok` while dropping `providerExtraModels` / `providerHiddenModels`, so model-list edits made from a newer desktop were lost silently. A 2.2 client now refuses such a daemon at handshake. Keep the desktop and the sidecar on the same release line — a registered system-service daemon can outlive a desktop upgrade.
- `@taco-ai/sidecar` now depends on `@taco-ai/pi-harness@0.1.0` instead of `@earendil-works/pi-agent-core`, and on `@earendil-works/pi-ai@1.3.0` instead of `0.99.2`. The on-disk session format is unchanged, so existing sessions keep opening. Anyone embedding the sidecar and reaching into `pi-agent-core` directly has to move to `@taco-ai/pi-harness`.
- `commandPermissions.rules` is still accepted on disk and is normalized into `allow`. `deny` means "always ask", `allow` means "allowed unless a deny rule matches" — a rule that used to be an allowlist in `auto` mode is no longer one.
- The tree-sitter bash and PowerShell grammars are bundled into the sidecar and the desktop artifact; no separate download is needed.
- An IM policy file written by 0.2.10 or earlier is migrated the first time it is loaded: every `auto` layer becomes `ask`. The file is rewritten with a policy document version, and the migration runs only on files that carry none.
