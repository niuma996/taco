# v0.2.2 Release Notes

> Released: 2026-09-14
> `desktop-v0.2.2` · `@taco-ai/{protocol,shared,sidecar,cli}@0.2.2`

A small follow-up to 0.2.1: mid-run steer and follow-up across the wire, and scheduled jobs gain real fire reporting plus run caps so a one-shot "fire now" doesn't have to fake a long interval.

---

## English

### Features

- **Mid-run steer and follow-up** — inject a message into a running turn (`session.steer`) or queue one to run after it ends (`session.followUp`); `session.cancelQueued` removes a queued follow-up. The protocol bumps to 2.1 and `session.steer` now returns `{ mode, entryId }` so a 2.0 daemon can't be misread as a successful enqueue — `sidecar` + `desktop`
- **Scheduled job run caps** — `max_runs` caps accepted fires, `max_consecutive_failures` is a circuit breaker (default 5, `0` disables). Exhausting either cap sets `enabled: false`, records the reason, and detaches the timer; re-enabling from the UI clears the breaker — `sidecar`

### Improvements

- **Workspace toolset converges every turn** — the workspace rebuilds its toolset at the start of every turn and merges the result into the active session toolset, so policy / IM / extension changes reach a live conversation on its next message without per-source invalidation plumbing. Name-comparison guard keeps the steady state byte-identical — `sidecar`

### Fixes

- **Job fires report the real outcome** — `runNow` / `runJob` return `JobRunResult { status, error }` (`ok` / `skipped` / `failed`); the `jobsRunNow` tool and its description spell out that "ok" means the fire was *accepted*, not that the turn completed — `sidecar` + `desktop`
- **Self-fired jobs no longer self-deadlock** — a job force-fired from inside its own IM conversation degraded from `session.prompt` to a queued `session.followUp` (same busy fallback IM ingress already had), and retries once if the lane reports idle — `sidecar`
- **Session active-tool allowlist re-aligns on attach** so it matches the workspace's view, with retryable candidates exempted so a transient `allowlist_missing` retry doesn't trigger a re-alignment cycle — `sidecar`
- **`officecli` skill directory ships inside the desktop bundle** so the skill resolves without an extra fetch — `desktop`

## 中文

### 新功能

- **运行中插话与续接** —— 在进行中的 turn 注入消息（`session.steer`），或在 turn 结束后排队执行（`session.followUp`）；`session.cancelQueued` 撤销已排队的续接。协议升至 2.1，`session.steer` 返回 `{ mode, entryId }`，避免 2.0 daemon 的 `null` 被误读成成功入队 — `sidecar` + `desktop`
- **定时任务运行上限** —— `max_runs` 限制已接受触发次数，`max_consecutive_failures` 是熔断器（默认 5，`0` 关闭）。任一上限耗尽即置 `enabled: false`、记录原因并解绑定时器；从 UI 重新启用会清空熔断计数 — `sidecar`

### 优化

- **工作区工具集每轮收敛** —— 每轮 turn 起始重建工具集并合并到 session 活跃集合，使策略 / IM / 扩展变更无需按源失效，下条消息即可生效；按名比对让稳态零改动、KV-cache 不抖动 — `sidecar`

### 修复

- **任务触发回报真实结果** —— `runNow` / `runJob` 返回 `JobRunResult { status, error }`（`ok` / `skipped` / `failed`）；`jobsRunNow` 工具及其说明强调"ok"仅代表触发被*接受*，不代表 turn 完成 — `sidecar` + `desktop`
- **自身触发不再自死锁** —— 在所属 IM 会话内被 force-fire 的任务，`session.prompt` 被 busy 拒绝时降级为排队 `session.followUp`（与 IM ingress 走同一条 busy 退路），并在 lane 报告空闲时重试一次 — `sidecar`
- **附着时回齐 session 活跃工具白名单**，与工作区视图一致；可重试候选项豁免，避免瞬态 `allowlist_missing` 触发反复回齐 — `sidecar`
- **`officecli` skill 目录随 desktop 打包**，免去额外拉取即可解析 — `desktop`

## Upgrade notes

- Workspace versions advance `0.2.1 → 0.2.2`. Wire protocol advances `2.0 → 2.1` (additive, but `session.steer` is now expected to return `{ mode, entryId }`); a 2.0 daemon stays compatible with 2.1 clients, but a 2.1 client paired with a 2.0 daemon can misread a steer `null` as a successful enqueue — keep the desktop and sidecar on the same release line.
- `max_runs` and `max_consecutive_failures` default to `undefined` on legacy jobs (`max_consecutive_failures` resolves to the current default of 5 on read), so existing schedules continue to run; new caps only apply when set.
