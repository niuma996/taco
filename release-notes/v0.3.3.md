# v0.3.3 Release Notes

> Released: 2026-10-30
> `desktop-v0.3.3` · `@taco-ai/{protocol,shared,sidecar,cli}@0.3.3`

A release about the agent learning to see: you can hand it any file, it can read
a PDF, look at a picture, and answer a question about the photo you sent it
from a chat app.

---

## English

### Features

- **Attach any file** — the desktop attaches any file type now, up to 8 per
  message and 25 MB each — `desktop`
- **PDFs the agent can read** — `read` extracts the text layer of a PDF, and
  renders the first 5 pages of a scan as images — `sidecar`
- **PDF editing tools** — `pdfMerge`, `pdfSplit`, `pdfFill` and `pdfFields`
  merge, split, fill and inspect PDF forms — `sidecar`
- **Images the model can see** — pictures returned by MCP tools are forwarded
  to the model, and a model you added yourself can declare image input — `sidecar` + `desktop`
- **Photos sent from chat apps** — pictures and files from WeChat and WeCom
  reach the model now — `sidecar`
- **One question per photo** — a photo and its caption sent in a chat app
  arrive as one message, not two — `sidecar`

### Improvements

- **Command approvals in chat apps no longer hang** — they are refused right
  away, and the model tells you what it wanted to do instead — `sidecar`
- **Request errors name the field** — RPC parameters are validated, and a
  rejected request reports which field was wrong — `all`
- **Destructive actions ask first** — deleting an MCP server, a permission rule
  or a scheduled task asks for confirmation now — `desktop`
- **Screen readers hear errors** — failures across the settings panels are
  announced instead of staying silent — `desktop`

### Fixes

- **Changing a setting no longer interrupts conversations** — memory, system
  prompt and MCP changes no longer stop the sessions that are running — `sidecar`
- **Settings save again** — a stale config lock no longer makes every save
  time out — `sidecar`
- **The daemon stays small** — the error log is capped and rotates, and the
  push log no longer stalls the app — `sidecar`
- **The desktop reconnects** — after restarting the sidecar from inside the
  app, it connects again on its own — `desktop`
- **Attachment thumbnails render** — a picture you send in a chat shows up in
  the message — `desktop`
- **Existing sessions get new tools** — a tool installed after a session was
  created is available in that session — `sidecar`
- **Fewer approval prompts** — the shell tool no longer reaches for
  here-documents, which always needed approval — `sidecar`

### Breaking changes

- **Wire protocol 2.4 → 2.6** — keep the desktop and the sidecar on the same
  release line; a newer desktop refuses an older daemon at startup — `sidecar` + `desktop`

## Upgrade notes

- Versions advance `0.3.2 → 0.3.3` across `desktop`, `protocol`, `shared`, `sidecar` and `cli`.
- Wire protocol advances `2.4 → 2.6`. Keep the desktop and the sidecar on the
  same release line — a registered system-service daemon can outlive a desktop
  upgrade.
- Attachments: up to 8 per message and 25 MB per file. A pasted image is
  capped at 8 MB. Staged files live in the session's `attachments/` folder and
  are removed with the session.
- Rendering a scanned PDF needs the optional native renderer
  `@napi-rs/canvas@1.0.13`. Without it the text layer still works, and the
  install command is printed instead of an error.
- The four PDF tools load on demand, and their output paths are fenced to the
  workspace like `write` and `edit`.
- RPC parameters are validated now. A script or third-party client that sent
  malformed requests will be rejected with `invalid_params` and a field path.
