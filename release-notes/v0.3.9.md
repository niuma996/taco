# v0.3.9 Release Notes

> Released: 2026-11-09
> `desktop-v0.3.9` · `@taco-ai/{protocol,shared,sidecar,cli}@0.3.9`

A release about background work that can wait for you — a scheduled job or a
background agent that needs an answer now says so, can be stopped, and no
longer gets lost when the connection drops. The chat also grew a memory of
its own: every conversation keeps its own draft, its own state and its own
attachments.

---

## English

### Features

- **Background work can wait for you** — a scheduled job or a background agent
  that pauses for an answer or a command approval shows as "waiting" in the
  Work pane, together with what it is waiting on; running and waiting tasks
  can be stopped there, and finished records can be deleted — `desktop` +
  `sidecar`
- **Sending an answer twice is safe** — a lost response or a restart no longer
  loses your answer; resubmitting the same answer continues the same run
  instead of repeating it — `sidecar`
- **Each chat keeps its own draft** — text, attachments and the chosen model
  are remembered per chat, and a message that may not have been delivered can
  be pulled back into the input box — `desktop`
- **Notifications stay with the account that started the work** — a finished
  background task is still delivered after a token refresh, but switching
  accounts no longer sends the old notification to the new one — `sidecar`
- **Stopped agents keep what they found** — a subagent that is cancelled or
  times out returns the partial results it had already produced, so you can
  see how far it got — `sidecar`

### Improvements

- **The composer tells you where the conversation stands** — sync pending, run
  state unconfirmed and partially shown history are surfaced under the input
  box, and "open chat" reaches the conversation that is actually waiting on
  you — `desktop` + `sidecar`
- **Waiting questions expire on their own** — a question left unanswered for
  seven days is closed and kept as a record; late answers are refused instead
  of reviving a dead run — `sidecar`
- **IM channels got friendlier** — the assistant asks its question in the
  reply instead of raising an error it cannot show, re-binding a WeChat
  account can be cancelled instead of hanging on the QR login, and an
  explicit request for a reply language now wins over the configured one —
  `sidecar`
- **The assistant converges instead of over-checking** — project instructions,
  skills and memories can no longer override the core rules, and a scoped task
  is no longer widened into an open-ended investigation — `sidecar`

### Fixes

- **Switching chats no longer mixes them up** — late responses from a previous
  chat are discarded, state is kept per chat, history that fails to load is
  reported instead of rendered as an empty conversation, and merging history
  with live updates no longer loses or duplicates messages — `desktop`
- **Answers and attachments survive a failure** — an answer that fails to
  submit keeps its question card so you can send it again, and pasted image
  previews and the model choice no longer break when you switch chats —
  `desktop`
- **Stopping no longer kills the next run** — a stop request is matched to the
  run it was meant for, text dropped by a stop returns to the chat that asked
  for it, and approvals from before a restart are not offered again —
  `desktop`
- **Work bookkeeping is more accurate** — a late result from an earlier
  attempt can no longer overwrite a run that is still waiting, work records
  recover after a crash instead of being marked failed, and deleting a chat
  marks the work attached to it as interrupted rather than leaving it
  "running" forever — `sidecar`
- **Unbound channels and IM routing behave** — cleared credentials are
  honoured even if a default remains in the config file, and work started on
  an IM channel finds the right conversation — `sidecar`

## 中文

### 新增

- **后台工作会等你回应** —— 定时任务或后台智能体停在提问、命令审批时，Work 面板会显示
  「等待中」并说明它在等什么；运行中、等待中的任务可以在那里停止，已结束的记录可以
  删除 —— `desktop` + `sidecar`
- **回答重发不再重复执行** —— 响应丢失或进程重启后，重发同一份回答会接着上一次的运行
  继续，不会再跑一遍 —— `sidecar`
- **每个聊天有各自的草稿** —— 输入文字、待发送附件和所选模型按聊天分别记住；发送结果
  不确定时，还可以把原文一键取回输入框 —— `desktop`
- **通知留在发起时的那个账号** —— 刷新凭据后工作结果依然能送达，但换账号不会把旧通知
  发到新账号上 —— `sidecar`
- **被停止的智能体保留已有结论** —— 被取消或超时的子代理会带上它已经得出的部分结果，
  你能看到它做到哪一步 —— `sidecar`

### 优化

- **输入框会说明当前对话的状态** —— 同步未完成、运行状态待确认、仅显示部分消息等情况
  都会显示在输入框下方；「打开聊天」也能定位到真正在等你的那个对话 —— `desktop` +
  `sidecar`
- **等待中的提问会自动过期** —— 七天没有回答的提问会被关闭并保留记录；迟到的回答会被
  拒绝，而不是唤醒一个已经结束的运行 —— `sidecar`
- **IM 渠道用起来更顺** —— 助手改为在回复里直接提问，不再抛出那里根本显示不了的错误；
  微信重新绑定可以取消，不会卡在扫码上；你明确指定回复语言时以你的为准 —— `sidecar`
- **助手会收敛而不是无限检查** —— 项目指令、skills 和记忆不能覆盖核心约束，有明确范围
  的任务也不会被扩成开放式调查 —— `sidecar`

### 修复

- **切换聊天不再串台** —— 来自上一个聊天的迟到响应会被丢弃，状态按聊天分别保存；历史
  加载失败会如实提示，而不是渲染成一个空聊天；历史与实时消息合并时也不会再丢消息或
  重复 —— `desktop`
- **回答与附件不再半路丢失** —— 回答提交失败时问题卡片会保留，可以再次发送；粘贴的
  图片预览和所选模型也不会因为切换聊天而失效 —— `desktop`
- **停止不会误停下一轮运行** —— 停止请求会精确匹配它针对的那次运行，被中断丢掉的文字
  回到发起它的那个聊天，重启前的审批请求也不会再次弹出 —— `desktop`
- **工作记录更准** —— 来自旧尝试的迟到结果不会再覆盖仍在等待的运行；崩溃后工作可以
  恢复而不是一律判为失败；删除聊天会把绑在上面的工作标记为中断，不再永远停在
  「运行中」 —— `sidecar`
- **渠道解绑与 IM 路由恢复正常** —— 即使配置文件里还留着默认凭证，已清除的凭证也会被
  正确识别；在 IM 渠道发起的工作也能定位到正确的对话 —— `sidecar`

## Breaking changes

- **The protocol moved to 2.13 and Work gained a "waiting" status** — clients
  that do not announce `workWaiting` keep receiving `running`, so older
  desktops keep working. `work.cancel` and `work.delete` are new RPC methods;
  a sidecar that predates them answers `unsupported`. Keep the desktop and
  the sidecar on the same release line — `sidecar` + `cli`
- **The work store does not downgrade** — a daemon older than 2.11 cannot read
  the new work records, so rolling back needs a matching backup — `sidecar`
- **One question, one answer** — resubmitting a *different* answer for a
  question that was already answered is refused with `invalid_state`, and a
  question left for seven days or cancelled with its work no longer accepts
  an answer — `sidecar`

## Upgrade notes

- Versions advance `0.3.8 → 0.3.9` across `desktop`, `protocol`, `shared`,
  `sidecar` and `cli`.
- **Desktop and sidecar should be upgraded together.** The Work pane's stop
  and delete actions, and the "waiting" status, need a sidecar from this
  release.
- **Deliveries are still at-least-once.** Deleting a work record does not
  recall a message the platform already accepted, and a new account will not
  receive an old notification.
