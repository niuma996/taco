# v0.4.0 Release Notes

> Unreleased

This release brings workspace and IM conversations into one sidebar, adds
layered configuration and memory, and lets child agents keep working in the
same conversation — including the new Codex runtime.

---

## English

### Features

- **Workspace and IM conversations share one sidebar** — browse and search
  conversations across workspaces, keep groups expanded, and see activity,
  unread messages, and waiting interactions without switching each workspace
  into view — `desktop`
- **Configuration has explicit source layers** — Agents and Skills can show
  effective, global, workspace, and builtin definitions. Read original sources
  even when shadowed; edit Taco-owned global and workspace agents without
  switching the active chat — `desktop` + `sidecar`
- **IM memory has its own partition and inherited sources** — each conversation
  keeps separate topic memory, reads associated workspace memory, and can opt
  into memory from other local workspaces managed by the running sidecar.
  Inherited topics are read-only; scoped references retrieve their full bodies
  without opening additional filesystem paths — `desktop` + `sidecar`
- **Scheduled and inbound IM work use a durable queue** — persist inbound
  receipts and message batches, preserve per-session order, and recover the
  original accepted operation after a restart. Inbound work appears in the Work
  pane with its execution and delivery status — `sidecar` + `desktop`
- **Agent sessions support ongoing conversations** — `chatToAgent` sends
  context or follow-up tasks to an existing child; `listAgentSessions` discovers
  its children or same-parent siblings. Receipts distinguish acceptance from
  completion, and results still go to the original parent — `sidecar` + `desktop`
- **Claude Code agents can continue natively** — retain native sessions for
  later messages through `chatToAgent`. Running conversations deliver at the
  next turn; they do not promise to interrupt an active tool — `sidecar`
- **Codex subagents are now available** — install the official SDK runtime
  from Agents and configure Codex agents with native thread resume. The Agents
  page and Codex form show installation and sign-in status, offer a login
  command when needed, and show manual installation instructions when npm is
  unavailable. Messages to a running child queue until its turn settles —
  `sidecar` + `desktop`
- **External agents can communicate through Taco** — Claude Code and Codex
  receive the permitted `chatToAgent` and `listAgentSessions` MCP tools for each
  run. Taco binds the sender identity and checks which sessions it may address
  — `sidecar`
- **Plan-mode file writes can be approved individually** — a proposed file
  write outside the plan directory, within the workspace or its associated
  directories, can be approved without exiting plan mode. Approval covers that
  path for the current plan; shell writes remain blocked — `sidecar` + `desktop`

### Improvements

- **Recovery preserves the state of each conversation** — reconnect restores
  partial replies, active tools, queued input, pending approvals, and child
  continuations. Child progress remains attached to the original agent card,
  and the panel reconciles live updates with full history — `desktop` + `sidecar`
- **Catalogs and chat presentation are more consistent** — shared pane
  controls, lighter headings, wider agent/plugin layouts, rounded markdown
  tables, and message metadata shown on hover — `desktop`
- **Communication guidance matches the available tools** — prompts explain
  discovery, delivery receipts, sibling scope, and the need to send later
  parent context explicitly. Saved memory and project context cannot supply
  new approvals through embedded control tags — `sidecar`
- **Storage and queue bookkeeping do less repeated work** — atomic file
  publishing protects task lists and results from partial writes; queue
  scheduling reads open entries and prunes finished queue records — `sidecar`

### Fixes

- **Navigation cannot leave a newer chat stuck loading** — stale cross-workspace
  new-chat requests no longer cancel a later selection. Restored expanded
  groups load their sessions, and chat-only panels close when leaving chat —
  `desktop`
- **Agent edits preserve their original definition** — custom filenames and
  shadowed global definitions remain readable and editable; unchanged cwd
  settings and Codex communication-tool restrictions survive saves — `sidecar`
  + `desktop`
- **Stopping and replaying Work respects execution identity** — deferred
  cancellations remain effective during recovery, replayed inbound batches
  keep their own waiting questions, and self-fired jobs return acceptance
  without waiting on the session running the tool — `sidecar`
- **Child-message receipts reflect what happened** — unconsumed follow-ups
  cleared by a turn limit are not reported completed; messages consumed together
  do not trigger duplicate continuations, and shutdown settles active receipts
  before clearing execution state — `sidecar`
- **Failed plan answers keep plan mode active** — cancelled or expired Work,
  busy admission, and receipt persistence failures cannot prematurely approve
  the plan; retries remain tied to the reviewed plan — `sidecar`
- **Opening a local file or folder works again** — the action that opens the
  workspace folder or a session log in the browser now opens the path instead
  of doing nothing — `desktop`

### Breaking changes

- **`agentContinue` has been removed** — use `chatToAgent` for running messages
  and idle continuation. Existing history remains readable, but old calls
  render as ordinary tool records and do not participate in subagent topology
  or execution recovery. Incomplete legacy calls are not resumed automatically
  — `all`
- **The protocol advances from 2.13 to 2.18** — the new desktop needs matching
  support for scoped catalogs, layered memory, and `memory.read`. Older clients
  retain capability-based projections for inbound Work and memory layers — `all`

### Upgrade notes

- Upgrade the desktop and sidecar together; the daemon may need a restart to
  load the new protocol and runtime code.
- Codex agents use the provider, model, and credentials in your own Codex
  configuration under `$CODEX_HOME` (default `~/.codex`). Leave the model empty
  to inherit it. A custom provider with its own credentials needs no OpenAI
  login. Claude Code continues to require its local CLI and Agent SDK; the
  managed installation card described above is specific to Codex.
- Native Claude Code and Codex session records are separate from Taco's display
  history. Native persistence supports resume, but does not guarantee that SDK
  sessions appear in the original application's conversation list. Older
  Claude Code history without a native session mapping cannot be resumed.
- IM topic memory now uses the full conversation identity. Topic memory stored
  under the older shared scratch identity is not automatically copied into
  conversations; review it before moving any notes. Human-maintained `MEMORY.md`
  remains shared. Associated and system topic layers are inherited read-only.
- Delivery to IM platforms remains at-least-once. Interrupted child messages
  whose delivery cannot be confirmed are not automatically resent. Old inbox
  batches left dispatching without a Work handoff marker are also not replayed
  automatically, because their earlier outcome is ambiguous.

## 中文

### 新功能

- **工作区与 IM 对话集中在同一侧栏** —— 跨工作区浏览和搜索对话，保留分组展开状态，
  查看运行活动、未读消息和待回应事项，无需逐个切换工作区 —— `desktop`
- **配置来源分层展示** —— Agents 和 Skills 可查看生效、全局、工作区和内置定义；
  被覆盖的原始定义仍可读取，编辑 Taco 管理的全局与工作区代理时无需切换当前聊天 ——
  `desktop` + `sidecar`
- **IM 记忆独立存储并支持继承** —— 每个对话有独立主题记忆，可读取关联工作区记忆，
  并按策略选择继承当前 sidecar 管理的其他本地工作区记忆。继承主题只读，可通过带来源
  标识的引用读取完整正文，无需扩大文件读取范围 —— `desktop` + `sidecar`
- **定时任务与 IM 入站工作使用持久队列** —— 入站回执和消息批次先落盘，按会话保持
  顺序，重启后恢复原本已接受的操作；Work 面板展示入站工作的执行和投递状态 ——
  `sidecar` + `desktop`
- **子代理会话可以持续交流** —— `chatToAgent` 向已有子代理补充上下文或发送后续任务，
  `listAgentSessions` 发现自身子代理或同父兄弟；回执区分接受与完成，结果仍发送给
  最初的父会话 —— `sidecar` + `desktop`
- **Claude Code 子代理支持原生续聊** —— 保留原生会话，通过 `chatToAgent` 接收后续
  消息；运行中的消息在下一轮交付，不承诺打断正在执行的工具 —— `sidecar`
- **新增 Codex 子代理** —— 可在 Agents 页面安装官方 SDK 运行时、配置 Codex 子代理，
  并通过原生线程继续对话。Agents 页面和 Codex 表单展示安装与登录状态，需要时提供
  登录命令；应用找不到 npm 时显示手动安装说明。运行中的消息排队等待当前回合结束 ——
  `sidecar` + `desktop`
- **外部子代理可通过 Taco 通信** —— Claude Code 和 Codex 每次运行可获得获准的
  `chatToAgent` 与 `listAgentSessions` MCP 工具；发送者身份由 Taco 绑定，
  可通信的目标范围由 Taco 校验 —— `sidecar`
- **计划模式支持按路径审批写入** —— 对工作区或关联目录内、计划目录之外的文件写入，
  可在不退出计划模式的情况下单独审批；授权仅对当前计划中的该路径生效，shell 写入
  仍被阻止 —— `sidecar` + `desktop`

### 优化

- **恢复时保留每个对话的状态** —— 重连恢复未完成回复、活动工具、排队输入、待审批
  请求和子代理续聊；子代理进度始终关联原始代理卡片，面板补齐完整历史并合并实时更新 ——
  `desktop` + `sidecar`
- **目录面板与聊天呈现更一致** —— 统一面板控件、减轻标题字重、扩展代理和插件布局，
  Markdown 表格使用圆角，消息元信息在悬停时显示 —— `desktop`
- **通信引导与实际工具保持一致** —— 提示词明确实例发现、异步回执、同父兄弟范围，
  以及后续父会话上下文需要显式发送；记忆和项目上下文中的控制标签不能提供新审批 ——
  `sidecar`
- **存储与队列减少重复工作** —— 原子发布文件，避免任务列表和结果被部分写入；
  调度仅读取未结束的队列项，并清理已结束的队列记录 —— `sidecar`

### 修复

- **导航不再让新选择的聊天卡在加载中** —— 过期的跨工作区新建请求不再取消后续选择；
  恢复展开分组时加载其中的会话，离开聊天时关闭专属右面板 —— `desktop`
- **代理编辑保留原始定义** —— 自定义文件名和被遮蔽的全局定义可正常读取、编辑；
  未变化的工作目录和 Codex 通信工具限制在保存后保留 —— `sidecar` + `desktop`
- **停止与重放 Work 遵守执行身份** —— 延后的取消请求在恢复时仍有效，重放入站批次
  不会取消自己的待回答问题；会话触发自身定时任务后返回接受结果，不再等待自身释放
  会话 —— `sidecar`
- **子代理消息回执反映实际状态** —— 回合上限清除的未消费消息不再被报告为完成，
  同轮处理的消息不再重复启动续聊，退出时先结算活动回执再清理执行状态 —— `sidecar`
- **计划回答失败时保留计划模式** —— Work 已取消或过期、会话忙碌、回执保存失败时，
  不会提前批准计划；重试仍绑定已审阅的原计划 —— `sidecar`
- **打开本地文件或文件夹恢复正常** —— 在浏览器中打开工作区目录或会话日志的操作现在
  能真正打开路径，不再毫无反应 —— `desktop`

### 破坏性变更

- **`agentContinue` 已移除** —— 运行中插话和空闲续聊统一使用 `chatToAgent`。
  已有历史仍可读取，但旧调用仅按普通工具记录展示，不再参与子代理拓扑和执行恢复；
  未完成的旧调用不会自动恢复 —— `all`
- **协议从 2.13 升至 2.18** —— 新桌面端需要配套的配置分层、分层记忆和 `memory.read`
  支持；旧客户端按能力声明接收入站 Work 和记忆层的兼容结果 —— `all`

### 升级说明

- 请同时升级桌面端与 sidecar；常驻 daemon 可能需要重启才能加载新协议和运行时代码。
- Codex 子代理沿用 `$CODEX_HOME`（默认 `~/.codex`）中的 provider、模型和凭据，模型
  留空即继承该配置；自带凭据的第三方 provider 不需要 OpenAI 登录。Claude Code 仍需
  安装本地 CLI 与 Agent SDK，上述应用内安装卡片仅适用于 Codex。
- Claude Code 和 Codex 的原生记录与 Taco 显示历史分别保存。原生持久化支持续聊，
  不保证 SDK 会话出现在原应用的聊天列表中；缺少原生会话映射的旧 Claude Code 历史
  无法续聊。
- IM 主题记忆改为按完整对话身份隔离。旧共享 scratch 身份下的主题不会自动复制到
  各对话，请审阅后再移动需要的笔记。人工维护的 `MEMORY.md` 仍共享，关联与系统主题层
  以只读方式继承。
- IM 平台投递仍是至少一次。中断后无法确认送达的子代理消息不会自动重发；旧 inbox 中
  处于 dispatching 且缺少 Work 交接标记的批次也不会自动重放，以免重复执行结果不明的
  旧操作。
