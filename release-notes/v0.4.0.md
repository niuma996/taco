# v0.4.0 Release Notes

> Unreleased

Agent sessions can now stay in conversation: send new context while work is
running, continue the same session after it settles, and let sibling agents
coordinate without creating a new agent for every message.

---

## English

### Features

- **Agent sessions support ongoing conversations** — `chatToAgent` sends a
  follow-up or an interjection to an existing child, with an asynchronous
  delivery receipt by default and completion still reported to the original
  parent. `listAgentSessions` discovers communicable children and same-parent
  siblings without exposing unrelated sessions — `sidecar` + `desktop`
- **Claude Code agents can continue natively** — supported Claude Code children
  retain their native session and accept later messages through `chatToAgent`;
  running conversations deliver at the next turn rather than promising to
  interrupt an active tool — `sidecar`
- **Codex agents use the official SDK** — a pinned `@openai/codex-sdk` runtime
  can be installed from Agents settings, supports native thread resume, and
  keeps running messages in a durable Taco queue until the current turn settles
  — `sidecar` + `desktop`
- **Codex child communication is host-bound** — a per-run stdio MCP bridge
  exposes only `chatToAgent` and `listAgentSessions`; sender identity cannot be
  forged by the child — `sidecar`
- **Continuations retain their execution identity** — the desktop attaches
  progress and settlement to the original agent card, ignores stale run
  receipts, and restores active continuations after reconnecting — `desktop` +
  `sidecar`

### Improvements

- **Communication guidance matches the available tools** — prompts and tool
  descriptions explain discovery, delivery receipts, sibling scope, and the
  need to send later parent context explicitly — `sidecar`
- **Runtime setup distinguishes install from sign-in** — Codex status,
  install, and the managed login command are visible on the Agents page and in
  the agent form. A machine without npm sees the terminal command instead of a
  failing Install button — `desktop`

## Breaking changes

- **`agentContinue` has been removed** — use `chatToAgent` for both running
  messages and idle continuation. The old tool is no longer registered, and
  `AgentContinueToolDetails` is no longer exported. Existing history remains
  readable, but old `agentContinue` calls render as ordinary tool records and
  do not participate in subagent topology or execution recovery. Incomplete
  legacy calls are not resumed automatically — `all`

## Upgrade notes

- Upgrade the desktop and sidecar together so continuation lifecycle pushes
  and active-run recovery are available on both ends.
- An interrupted message whose delivery cannot be established is reported as
  uncertain rather than resent automatically.
- Install the Codex runtime from Agents before using a Codex agent.
  Installation downloads a platform-specific binary and can take a minute;
  the setup card shows the elapsed time. The in-app installer requires npm;
  without it, Agents shows the exact terminal command instead of a button
  that cannot succeed.
- A Codex agent runs on your own Codex configuration — the provider, model,
  and credentials under `$CODEX_HOME` — the same way a Claude Code agent uses
  your Claude settings. A third-party provider with its own credentials needs
  no OpenAI login, so the model field can be left empty to inherit the model
  from that configuration. The login command appears only when the
  configuration points at OpenAI without a login.

## 中文

### 新功能

- **子代理会话可以持续交流** —— `chatToAgent` 可向已有子代理插话或发送后续任务，
  默认立即返回异步送达回执，完成通知仍发送给最初的父会话；
  `listAgentSessions` 只发现可通信的子代理和同父兄弟，不暴露无关会话 ——
  `sidecar` + `desktop`
- **Claude Code 子代理支持原生续聊** —— 支持续聊的 Claude Code 子代理会保留原生会话，
  通过 `chatToAgent` 接收后续消息；运行中的消息在下一轮交付，不承诺打断正在执行的工具 ——
  `sidecar`
- **Codex 子代理使用官方 SDK** —— 可在 Agents 设置中安装固定版本
  `@openai/codex-sdk`，支持原生线程续聊；运行中消息留在 Taco 持久队列，
  当前回合结束后再开始 —— `sidecar` + `desktop`
- **Codex 子代理通信由宿主绑定身份** —— 每次运行使用独立 stdio MCP bridge，
  只暴露 `chatToAgent` 和 `listAgentSessions`，子代理无法伪造发送者身份 —— `sidecar`
- **续聊保留运行身份** —— 桌面端把进度与完成状态关联到原始子代理卡片，忽略过期的运行
  回执，并在重新连接后恢复仍在执行的续聊 —— `desktop` + `sidecar`

### 优化

- **通信引导与实际工具保持一致** —— 提示词和工具描述明确说明实例发现、异步回执、
  同父兄弟范围，以及后续父会话上下文需要显式发送 —— `sidecar`
- **运行时安装与登录分开呈现** —— Agents 页面和 Agent 表单都会显示 Codex
  安装状态、安装操作和受管登录命令。找不到 npm 时显示终端命令，而不是一个
  必然失败的安装按钮 —— `desktop`

## 破坏性变更

- **`agentContinue` 已完全移除** —— 运行中插话和空闲续聊统一使用 `chatToAgent`。
  旧工具不再注册，`AgentContinueToolDetails` 也不再导出。已有历史记录仍可读取，但旧的
  `agentContinue` 调用只按普通工具记录展示，不再参与子代理拓扑或执行恢复；未完成的旧调用
  不会自动恢复 —— `all`

## 升级说明

- 请同时升级桌面端与 sidecar，确保两端都支持续聊生命周期推送和活动运行恢复。
- 如果中断后无法确定消息是否送达，系统会明确标记为不确定，而不会自动重发。
- 使用 Codex 子代理前，请先在 Agents 页面安装运行时。安装会下载平台相关二进制，
  可能需要一两分钟，配置卡片会显示已用时。应用内安装需要 npm；如果 sidecar 找不到
  npm，页面会给出终端命令，而不是一个必然失败的按钮。
- Codex 子代理运行在你自己的 Codex 配置上（`$CODEX_HOME` 下的 provider、模型和
  凭据），和 Claude Code 子代理沿用你的 Claude 设置是同一套规则。第三方 provider
  自带凭据，因此不需要 OpenAI 登录；模型留空即沿用该配置中的模型。只有当配置指向
  OpenAI 且缺少登录时，页面才会给出登录命令。
