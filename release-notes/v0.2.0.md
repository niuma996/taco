# v0.2.0 Release Notes

> Released: 2026-09-10
> `desktop-v0.2.0` · `@taco-ai/{protocol,shared,sidecar,cli}@0.2.0`

This release upgrades the sidecar to **Pi 0.85.1** end-to-end and brings the runtime into the long-lived daemon model that PR1–PR5 wired up. Tool-event naming, subagent depth facts, terminating-tool calls, and interrupted-run recovery were all adapted to Pi 0.85's new APIs.

---

## English

### Headline — Pi 0.85.1 migration

The sidecar now imports `pi-agent-core` and `pi-ai` pinned to **0.85.1**. User-visible behavior changes:

- **Streaming output works again.** Pi 0.85 moved the per-message payload to a new field; the desktop reader kept using the legacy one. The sidecar mirrors the new field back to the legacy one so streaming renders the same way it did on 0.83. The migration is not optional: switching to Pi's replay-frame stream would leave rendering empty for any provider that fills text at `text_start` — `sidecar` + `desktop`.
- **Terminating tool calls no longer fail the turn.** A run can legitimately close on a `toolResult` whose `terminate: true` (askUser / planExit). The wire type widens to accept that shape as a valid reply, and the sidecar surfaces the actual reason for "no reply" (model unavailable, hook decline, abort) instead of bubbling a role-mismatch error — `protocol` + `sidecar`.
- **Sidecar restart recovers interrupted runs.** If the sidecar was killed mid-turn, the next attach resumes the lane's own operation; the recovery status is logged so the reason the previous run stopped is visible in the daemon log. Subagent depth is read from `session.facts`, not derived from a path heuristic — so forks route correctly across restarts — `sidecar`.

### Features

- `cli` package promoted to a first-class daemon supervisor (`start` / `status` / `stop` / `install` / `uninstall` / `upgrade`); release builds attempt `taco install` to register a LaunchAgent (macOS) or Task Scheduler task (Windows) on first launch. Linux has no auto-service registration — `desktop` + `cli`
- Tray-resident desktop: system-tray entry, single-instance window, and the "Close hides to tray, Quit exits for real" lifecycle — `desktop`
- New-chat experience: cold start, workspace switch, and sidecar restart all land on a centered logo + rotating slogan instead of auto-opening the first session; the message bubbles and input card inset by 10% on each side when both side panels are collapsed, while the topbar background and scrollbar stay edge-to-edge — `desktop`
- Chat list renamed to "Chats" / "聊天列表" with unified row height; session bar gains a task-panel toggle with an unfinished-task awareness dot; context indicator moves into the input row and hides in the empty-chat splash — `desktop`

### Improvements

- README (English + Chinese) gains a "First-launch prompts on macOS / Windows" section explaining the Gatekeeper and SmartScreen workarounds for the unsigned binaries, plus the `xattr` and "More info → Run anyway" paths — `all`
- `pnpm release-age` gate restored for the Pi upgrade — pi 0.85.1 was published too recently to clear the default 24h policy and is listed in `pnpm-workspace.yaml` — `all`

### Fixes

- **Streaming output restored** — Pi 0.85's `message_update` payload shape was discarded by the sidecar reader; the re-introduced `normalizeMessageUpdate` mirrors `event` into the desktop's legacy field — `sidecar` + `desktop`
- **Terminating tool calls no longer fail the turn** — askUser / planExit closes are now accepted as valid prompt replies — `sidecar`
- **Interrupted runs report how they ended** — `completed` / `aborted` / `failed` / `interrupted` resume outcomes are logged, not just whether anything was recovered — `sidecar`
- **Subagent depth is read from `session.facts`**, not derived — eliminates the silent misrouting that the legacy `cwdDepth` heuristic caused on forks — `sidecar`
- **`session.list` warning narrowed** — the "encoding may have changed" warning no longer fires on legacy or never-named sessions, so it actually means something when it fires — `sidecar`
- **`one-shot` session handles close on completion** — no leftover socket keepalive, no zombie child processes on the worker — `sidecar`
- **Lane-busy errors translate to `session_busy`** in the RPC layer instead of bubbling as `AgentHarnessError` — `sidecar`
- **History rows no longer stamped with the load time** — earlier versions clobbered the server's `updatedAt` with `Date.now()` on fetch, hiding the real last-activity timestamp in the sidebar — `sidecar`
- **Prompt with no reply surfaces the real reason** — model_unavailable, hook decline, abort — instead of failing downstream with a generic role mismatch — `sidecar`
- **Channel routing — pin-session `imRouting` collision fixed** — the scheduler was overwriting the user's forward routing on every pin attach — `sidecar`
- **5 dead exports removed from sidecar**, 1 retained export documented via `@internal` JSDoc and tracked by `knip` — `sidecar`

## Upgrade notes

- **Pi version pin**: this release hard-pins `@earendil-works/pi-agent-core` and `@earendil-works/pi-ai` at `0.85.1`. The workspace release-age exception list covers this version; downstream workspaces do not need any change.
- **Wire event names**: consumers of the NDJSON protocol must use `tool_start` / `tool_update` / `tool_end` (not `tool_execution_*`). The desktop client is the only first-party consumer and is updated alongside this release.
- **`assistantMessage` widening**: third-party JSON-RPC consumers that already type-narrowed `CreateSessionResult.assistantMessage` to `AssistantMessage` need to widen their types to `AgentMessage` (or re-narrow at the call site). Returning a `toolResult` with `terminate: true` is now a valid reply shape.
- **`LaneBusy` and friends**: the `LaneBusy` error is now a tagged error, not a thrown `AgentHarnessError`. Use the `_tag` field or the `isBusyError` helper exported from `runtime/harnessErrors.ts`; do not use `instanceof HarnessFault` — that check returns `false` for tagged errors.
- **Daemon lifecycle**: the desktop no longer relies on a UI-owned stdio child. The CLI (`taco start` / `taco status` / `taco stop`) and the desktop now share the same daemon mode. `docs/02-architecture.md` will be updated to reflect this in the next docs pass; the README's "Quick Start" remains correct for both flows.
- **macOS / Windows installers**: there is no code-signing certificate yet. Expect the Gatekeeper and SmartScreen workarounds documented in the README on the first launch of a release binary.
