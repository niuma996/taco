# v0.3.1 Release Notes

> Released: 2026-10-23
> `desktop-v0.3.1` · `@taco-ai/{protocol,shared,sidecar,cli}@0.3.1`

A release about how far the agent may reach: a workspace can be granted extra directories, the agent can change your config once you approve, and a third-party conversation can no longer read your disk. The wire protocol moves 2.2 → 2.3, so upgrade the desktop and the sidecar together.

---

## English

### Features

- **Associated directories** — a workspace used to be a single root, so sibling directories were out of reach. A workspace or an IM channel can now be granted extra absolute paths, and the shell, the write tools and the agent editor may act inside them. MCP servers, extension tools and subagent tools stay anchored to the workspace's own root — `sidecar` + `desktop`
- **Config changes behind your approval** — the model had no way to touch `taco.json`, so it either guessed or asked you to edit the file by hand. Two deferred tools now read and patch the global config, and every patch goes through the approval prompt before it is written. API keys are never handed to the model, and a denial carries its reason so the model stops working around it — `sidecar` + `desktop`
- **Project-scoped agents** — the editor could only write `$TACO_HOME/agents`. It can now write `<workspace>/.taco/agents`, where a definition shadows a global one of the same name, and a `claude-code` agent can pin its own run directory — `sidecar` + `desktop`

### Improvements

- **The system prompt says where the agent is** — the model was told neither the working directory, nor the platform, nor the shell, and injected tags looked exactly like your own messages. An `<environment>` block now carries those facts, and every injected tag names its origin, so a system event cannot pass for your approval — `sidecar`
- **A declared context window survives a save** — the provider panel wrote the server default back on every save, overwriting the window you set. A session whose model was dropped from the catalog now also switches to a live model, preferring one on the same provider — `sidecar` + `desktop`

### Fixes

- **An IM conversation can no longer read the whole disk** — `read`, `grep` and `glob` were exempt from the path fence, so a conversation driven by someone else could read any file on the machine. The fence now covers them, and a custom IM execution directory can no longer point at `$TACO_HOME` and expose the API keys there — `sidecar` + `desktop`
- **Stopping the first turn no longer deletes the conversation** — a Stop click rejects the prompt call, and a rejected first prompt used to delete the new session along with messages already on disk — `desktop` + `sidecar`
- **No more "Session is already open"** — pi allows one open handle per session id, but only detached reads were queued; attaching to a freshly spawned subagent raced them. Create, read and attach are now serialized per id — `sidecar`

### Breaking changes

- **Wire protocol 2.2 → 2.3** — 2.3 adds `workspace.associations.*`, `config.patch` and the `workspace.associations_changed` push. A 2.3 client refuses a 2.2 daemon at handshake instead of failing on a single call later — `sidecar` + `desktop`

## 中文

### 新功能

- **关联目录** —— 过去一个工作区只有一个根目录，访问不到旁边的目录。现在可以为工作区或 IM 渠道关联额外的绝对路径，shell、写入工具和 agent 编辑器都能在这些目录中操作。MCP 服务、扩展工具和子代理工具仍只作用于工作区自身的根目录 — `sidecar` + `desktop`
- **需要审批的配置修改** —— 过去模型无法读写 `taco.json`，只能靠猜，或者让你手动改文件。现在新增两个按需加载的工具，用于读取和修改全局配置，每次修改都要先经你审批才会写入。API 密钥不会暴露给模型；修改被拒时会附上原因，模型不会再换个方式绕过去 — `sidecar` + `desktop`
- **项目级 agent** —— 过去编辑器只能写入 `$TACO_HOME/agents`。现在也可以写入 `<workspace>/.taco/agents`，其中的定义会覆盖同名的全局定义；`claude-code` agent 还可以固定自己的运行目录 — `sidecar` + `desktop`

### 优化

- **系统提示词包含运行环境** —— 过去模型不知道工作目录、平台和 shell，注入的 tag 看起来也和你发的消息没有区别。现在新增 `<environment>` 段落提供这些信息，每个注入的 tag 都会标明来源，系统事件不会再被当成你的批准 — `sidecar`
- **自定义的上下文窗口不再被覆盖** —— 过去 provider 面板每次保存都会写回服务端默认值，覆盖你设置的窗口大小。另外，会话使用的模型被移出目录后，会自动切换到可用的模型，优先选择同一 provider 下的模型 — `sidecar` + `desktop`

### 修复

- **IM 对话不能再读取任意文件** —— 过去 `read`、`grep`、`glob` 不受路径限制，由他人驱动的对话可以读取本机任何文件。现在这三个工具同样受限；IM 自定义执行目录也不能再指向 `$TACO_HOME`，避免泄露其中的 API 密钥 — `sidecar` + `desktop`
- **停止第一轮对话不再删除会话** —— 点击停止会让 prompt 调用失败，而过去第一轮 prompt 失败会把整个新会话删掉，包括已经保存的消息 — `desktop` + `sidecar`
- **不再报 "Session is already open"** —— pi 规定每个会话同一时间只能打开一个 handle，但过去只有分离读取会排队，打开刚创建的子代理时会与之冲突。现在同一会话的创建、读取和 attach 都按顺序执行 — `sidecar`

### 破坏性变更

- **线路协议 2.2 → 2.3** —— 2.3 新增 `workspace.associations.*`、`config.patch` 和 `workspace.associations_changed` 推送。2.3 客户端会在握手时直接拒绝 2.2 的 daemon，而不是等到调用某个方法时才失败 — `sidecar` + `desktop`

## Upgrade notes

- Versions advance `0.3.0 → 0.3.1` across `desktop`, `protocol`, `shared`, `sidecar` and `cli`.
- Wire protocol advances `2.2 → 2.3`. Keep the desktop and the sidecar on the same release line — a registered system-service daemon can outlive a desktop upgrade.
- Associated directories are stored in a new file, `$TACO_HOME/workspace-associations.json`; there is nothing to migrate.
- An agent definition may carry a `cwd:` frontmatter key. It must be an absolute path inside the workspace or one of its associated directories; a relative value is ignored.
