# v0.3.2 Release Notes

> Released: 2026-10-26
> `desktop-v0.3.2` · `@taco-ai/{protocol,shared,sidecar,cli}@0.3.2`

A release about memory that stops growing: a nightly job consolidates what the
agent learned, the model can search the questions you asked before, and a
session that used to take a minute to open now opens in a second. The wire
protocol moves 2.3 → 2.4, so upgrade the desktop and the sidecar together.

---

## English

### Features

- **Memory consolidation** — memory only ever grew: every extraction added topics, nothing merged duplicates or retired stale ones, and anything past the 100-topic injection cap silently vanished. A built-in nightly job now proposes merges, rewrites and archives per workspace in one model call, and the memory pane became its review surface — the plan, the run history and the archived entries, all visible before anything is written. The first plan for a workspace is always a preview, and every run can be undone — `sidecar` + `desktop`
- **The agent can search your own questions** — `sessionSearch` and `sessionList` let the model answer "have I asked about this before?" from the questions you typed in past sessions of the same workspace. They are deferred, so their schemas cost nothing until a question actually needs them — `sidecar`
- **A guide through your own messages** — the chat pane grew a rail of markers, one per message you sent: hover for a preview, click to jump, and the arrow keys, Home and End move between them. The rail follows the conversation as you scroll and lets go of the active marker once a jump settles — `desktop`

### Improvements

- **Opening a long session no longer stalls** — every message ran the markdown pipeline on the main thread and the transcript then filled in one message at a time, so the view jumped and the stick-to-bottom dropped out at random. Only the last ~40 messages render now, the highlighters are preloaded, and a skeleton holds the place while the history loads — `desktop`
- **A user-added model can think** — an added model was hard-coded to `reasoning: false`, so pi could not send `thinking: {type:"disabled"}` and a thinking model reasoned by default, spending the output budget on reasoning and sometimes returning no text at all. It now inherits the provider's reasoning flag, output cap, compat and thinking-level map — `sidecar` + `desktop`

### Fixes

- **Memory is extracted once per run** — extraction fired on every `turn_end`, which pi emits after each model response, so a 30-tool-call run extracted 30 times over the same transcript and injected ~18 KB of duplicated topics per call, with 53 of 153 topics silently dropped by the 100-entry cap. Extraction moved to `run_end`, sees the existing topics and updates them instead of adding duplicates — `sidecar`
- **Sidecar pushes arrive once** — concurrent `start()` calls each subscribed, because the field guarding the subscription was only set once `listen()` resolved; every push and every RPC response was parsed and dispatched twice, so a 2.8 MB history response paid for it twice — `desktop`

### Breaking changes

- **Wire protocol 2.3 → 2.4** — 2.4 adds `memory.dreamRun` / `.dreamApply` / `.dreamDiscard` / `.dreamUndo` and `memory.restoreTopic`, the `dream` / `dreamScheduled` fields on `memory.list`, and `Job.builtin` on `jobs.*`. A 2.4 client refuses a 2.3 daemon at handshake instead of failing on one call later — `sidecar` + `desktop`

## 中文

### 新功能

- **记忆整合** —— 记忆只会增长：每次提取都新增条目，从不合并重复、也不淘汰过时条目；超过 100 条注入上限的部分直接静默消失。现在有一个内置的夜间任务，在一次模型调用里为每个工作区提出合并、重写和归档的建议，记忆面板则成了它的审阅界面——合并方案、运行历史和已归档的条目，在写入任何内容之前都看得见。某个工作区的第一次整合永远只是预览，而且每一次整合都可以撤销 — `sidecar` + `desktop`
- **模型能检索你自己提过的问题** —— `sessionSearch` 和 `sessionList` 让模型可以从你在同一工作区历史会话中输入的问题里回答"我之前问过这个吗"。它们按需加载，不用时不会占用 token — `sidecar`
- **一条属于你自己的消息导轨** —— 聊天面板多了一列标记，每个由你发出的消息一个：悬停预览，点击跳转，方向键、Home 和 End 在标记之间移动。导轨随对话滚动更新，跳转落定后就交还当前标记 — `desktop`

### 优化

- **打开长会话不再卡顿** —— 每条消息都要在主线程跑一遍 markdown 流水线，随后对话再一条条填进来，于是视图会跳、贴底跟随也会随机失效。现在只渲染最后约 40 条消息，语法高亮器提前加载，加载期间用骨架占位 — `desktop`
- **手动添加的模型会思考了** —— 手动添加的模型被写死为 `reasoning: false`，pi 因此无法发送 `thinking: {type:"disabled"}`，会思考的模型于是默认一直在思考，把输出预算耗在推理上，有时甚至一个字都返回不了。现在它继承 provider 的 reasoning 标记、输出上限、compat 和思考档位映射 — `sidecar` + `desktop`

### 修复

- **记忆每次运行只提取一次** —— 提取挂在每个 `turn_end` 上，而 pi 在每次模型响应后都会发这个事件，于是带 30 次工具调用的运行会对同一份对话提取 30 次，每次调用注入约 18KB 的重复条目，153 条里有 53 条被 100 条的上限静默丢弃。提取已移到 `run_end`，它能看到已有条目，并改为更新而不是新增重复 — `sidecar`
- **sidecar 推送只到一次** —— 并发的 `start()` 各自订阅了一份，因为守护订阅的字段要等 `listen()` 兑现后才置位；结果每次推送和每次 RPC 响应都被解析并派发两遍，2.8MB 的历史响应为此付了双倍代价 — `desktop`

### 破坏性变更

- **线路协议 2.3 → 2.4** —— 2.4 新增 `memory.dreamRun` / `.dreamApply` / `.dreamDiscard` / `.dreamUndo` 与 `memory.restoreTopic`，`memory.list` 新增 `dream` / `dreamScheduled` 字段，`jobs.*` 新增 `Job.builtin`。2.4 客户端会在握手时直接拒绝 2.3 的 daemon，而不是等到调用某个方法时才失败 — `sidecar` + `desktop`

## Upgrade notes

- Versions advance `0.3.1 → 0.3.2` across `desktop`, `protocol`, `shared`, `sidecar` and `cli`.
- Wire protocol advances `2.3 → 2.4`. Keep the desktop and the sidecar on the same release line — a registered system-service daemon can outlive a desktop upgrade.
- Consolidation is on by default at 04:17 local time. The first plan for a workspace is a preview; scheduled runs apply on their own only after you have applied one once. Its schedule, thresholds and model live in the `memory-dream` built-in job under Schedules — the daemon seeds it, and it can be disabled but not deleted.
- Archived topics are kept under `archive/` inside the memory directory and can be restored from the memory pane.
- The desktop replaces the `mermaid` dependency with `pele`, which drops mermaid and its 109 transitive packages; the lazily loaded chart chunk shrinks from ~1.6 MB to ~250 kB gzip.
