# v0.4.1 Release Notes

> Released: 2026-11-15
> `desktop-v0.4.1` · `@taco-ai/{protocol,shared,sidecar,cli}@0.4.1`

This release makes workspaces removable, lets the assistant read saved memory in
full, and hardens the places where concurrent work used to collide — subagent
startup, scheduled jobs, and background results surviving a crash.

---

## English

### Features

- **Workspaces can be removed from the list, with optional data cleanup** — each
  workspace group gains an actions menu offering "remove from list" (source files
  and chat history stay) or "remove and clean Taco data". A cleanup preview lists
  exactly which Taco data will be deleted and which is retained, and the cleanup
  only runs after you confirm. Project folders, associated directories, custom
  execution directories, work records, scheduled job definitions, and inbox logs
  are always retained — `desktop` + `sidecar`
- **IM conversations can be hidden or deleted for good** — a hidden conversation
  only leaves the list, keeps its history and routing, and comes back with an
  unread badge when a new message arrives. Permanent deletion goes through the
  same preview and confirmation, and never touches other conversations in the
  same channel — `desktop` + `sidecar`

### Improvements

- **Saved memory can be read in full** — every memory entry handed to the
  assistant now carries a scoped read reference, so it can fetch the complete
  text instead of only the summary, and can trace an entry back to the
  conversation it came from. Active and archived topics share a versioned YAML
  codec; unmarked files keep their existing values — `sidecar`
- **Background results survive a crash** — the intent to settle a finished
  background agent is written to disk before the final state is recorded, and a
  restart replays those settlements first. A completion notice that arrives late
  says so explicitly, so the assistant corrects what it reported earlier —
  `sidecar`
- **Codex communication runs through the MCP SDK** — the bridge is packaged
  separately, shipped and verified by both npm and portable-runtime builds, and
  freezes the permissions granted for a run so later changes cannot widen it
  mid-flight — `sidecar`
- **Management panes stay in sync** — saving provider credentials immediately
  updates the model dropdown and the configured-provider count; a saved schedule
  shows its new configuration right away; schedule history and the Work pane read
  the same data instead of requesting it twice; panes refresh by themselves after
  the sidecar reconnects — `desktop`
- **Code search is more accurate and more robust** — `.gitignore` is honored
  reliably (including on Windows), binary files are skipped, and every match is
  counted. Without ripgrep, files over 2 MiB are skipped and the result states
  that the search was incomplete — `sidecar`

### Fixes

- **Concurrent subagent startup no longer breaks the session list** — a session
  file renamed while the list is being read is retried instead of failing the
  whole listing, and a freshly created child session is no longer dropped by a
  concurrent cache invalidation. A subagent that fails to start is now reported
  as an error, with the failing stage, and extensions no longer read a failed
  call as a success — `sidecar`
- **A scheduled job no longer runs twice** — a lock is only considered expired
  once the owning process is confirmed gone; a failed probe no longer deletes a
  lock that is still held — `sidecar`
- **Configuration patches no longer clear permissions or approved directories** —
  fields you do not mention keep their current value, and approved directories
  can no longer be changed through a patch — `sidecar`
- **Concurrent saves no longer overwrite each other** — IM policy and schedule
  settings are written serially, so editing a schedule while the scheduler is
  updating its counters no longer loses data — `sidecar`
- **A failed first question leaves no empty session behind** — rollback counts
  the messages actually on disk, so an empty session is reclaimed quietly while
  a session that already has content is kept — `sidecar`
- **Cleanup during shutdown no longer stops at the first failure** — channels
  and session resources are released one by one, so a single stuck component no
  longer leaves the rest half-open — `sidecar`

### Breaking changes

- **Task IDs are now unique within their list** — a task ID changed from
  `task-N` to `task-<listID>-N`. Existing task files are rewritten when they are
  read, but `taskUpdate` must use the exact ID returned by `taskList` — `all`

### Upgrade notes

- Upgrade the desktop and the sidecar together. The desktop replaces an
  outdated daemon on its own; if you registered the daemon as a system service
  with `taco install` and run the npm packages separately, upgrade it with
  `taco upgrade` or restart it — otherwise "remove and clean" reports that it
  cannot preview the cleanup fully and refuses to delete anything.
- Clearing the workspace list no longer re-seeds a default workspace on the next
  start. Reopening the folder restores the workspace and its history.
- A hidden IM conversation returns to the list only when it receives a new
  message.

### Downgrade notes

- Back up `$TACO_HOME/memory` before upgrading, and restore the backup before
  returning to a release without the memory codec. Older readers keep the YAML
  quote characters of special names and descriptions; writing from the old
  release can permanently change those values.
- Early codec files with quoted timestamps and block YAML sources also lose
  provenance on old readers. Quoted archive ages fail `Date.parse`, so their
  retention cleanup is silently skipped. New writes avoid this timestamp/source
  incompatibility; reads do not rewrite existing files.

## 中文

### 新功能

- **工作区可以从列表中移除，并可选地清理 Taco 数据** —— 每个工作区分组新增操作菜单，
  可选择「从列表移除」（源文件与聊天记录保留）或「移除并清理 Taco 数据」。清理前会
  预览逐条列出将要删除的 Taco 数据与保留的目录数据，确认后才执行。项目源文件夹、
  关联目录、自定义执行目录、工作记录、定时任务定义和收件日志一律保留 ——
  `desktop` + `sidecar`
- **IM 会话可以暂时隐藏或永久删除** —— 暂时隐藏只移出列表，保留历史与路由，
  收到新消息后自动回到列表并带未读标记；永久删除走同样的预览与确认流程，
  且不会牵连同一频道的其他会话 —— `desktop` + `sidecar`

### 优化

- **记忆可以读取完整正文** —— 交给助手的每条记忆都带一个带作用域的读取引用，
  它能取回完整正文而不只是摘要，也能追溯这条记忆来自哪次对话。活跃与归档主题
  共用带版本的 YAML codec，未标记的旧文件保持原有取值 —— `sidecar`
- **后台结果不再因崩溃丢失** —— 结算意图先落盘再写入终态，重启时先重放这些结算。
  迟到的完成通知会明确说明，助手据此更正此前的说法 —— `sidecar`
- **Codex 通信复用 MCP SDK** —— 桥接进程独立打包，随 npm 与便携运行时发布并做
  完整性检查；每次运行会冻结已授权的工具，中途变更不会扩大该次运行的权限 ——
  `sidecar`
- **管理面板的数据保持最新** —— 保存供应商凭据后模型下拉与「已配置供应商 N」计数
  立即更新；定时任务保存后立刻显示新配置；计划历史与 Work 面板读取同一份数据，
  不再重复请求；sidecar 重连后面板自动刷新 —— `desktop`
- **代码搜索更准更稳** —— 可靠遵守 `.gitignore`（Windows 同样生效），跳过二进制
  文件，统计完整命中数；没有 ripgrep 时超过 2 MiB 的文件会被跳过，结果中会说明
  搜索不完整 —— `sidecar`

### 修复

- **并发启动子代理不再让会话列表整体报错** —— 会话文件在列举期间被原子改名时，
  列表读取会自动重试；刚创建的子会话不会被并发的缓存失效抹掉。子代理启动失败
  现在会如实报错并标注失败阶段，扩展钩子不再把失败的调用当成成功 —— `sidecar`
- **定时任务不再被并发执行两次** —— 只有确认持锁进程已经消失才判定锁过期，
  探测失败不再删除仍在持有的锁 —— `sidecar`
- **配置补丁不再清空命令权限与授权目录** —— 未提及的字段保持当前取值，
  授权目录也不再能通过补丁修改 —— `sidecar`
- **并发保存不再互相覆盖** —— IM 策略与定时任务配置改为串行读写，
  在调度器更新计数的同时修改计划不会丢失数据 —— `sidecar`
- **首次提问失败后不残留空会话** —— 回滚按磁盘上的实际消息数判断，
  空会话被静默回收，写过内容的会话会被保留 —— `sidecar`
- **退出时的清理不再停在第一个失败** —— 渠道与会话资源逐个释放，
  单个组件卡住不会让其余资源留在半开状态 —— `sidecar`

### 破坏性变更

- **任务 ID 改为列表内唯一** —— 任务 ID 从 `task-N` 变为 `task-<列表ID>-N`。
  已有任务文件在读取时会自动改写，但 `taskUpdate` 必须使用 `taskList` 返回的
  原始 ID —— `all`

### 升级说明

- 请同时升级桌面端与 sidecar。桌面端会自动替换版本不匹配的旧 daemon；
  如果你用 `taco install` 把 daemon 注册为系统服务并单独运行 npm 包，
  需要 `taco upgrade` 或重启 daemon —— 否则「移除并清理」会提示无法完整预览清理内容，
  并拒绝删除任何数据。
- 手动清空工作区列表后不再自动补回默认工作区；重新打开该文件夹即可恢复
  工作区及其历史记录。
- 暂时隐藏的 IM 会话只会在收到新消息时回到列表。

### 降级说明

- 升级前备份 `$TACO_HOME/memory`，降至不支持记忆 codec 的旧版前恢复该备份。
  旧版会将特殊名称与描述的 YAML 引号读入字面值，旧版再次写入可能固化这些变化。
- 早期 codec 文件若使用带引号的时间戳和块式 YAML sources，旧版还会丢失来源。
  带引号的归档年龄无法通过 `Date.parse`，清理会静默跳过这些归档。
  新写入已避免时间戳和来源的不兼容；读取不会重写已存在文件。
