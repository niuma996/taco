# Memory admission and provenance

Memory topics remain Markdown files with frontmatter under `$TACO_HOME/memory/projects/<workspace-key>/`. The body covers one coherent durable theme, starts with its conclusion, and may include scope, reasons and exceptions as headings or lists. The hard limit is 2,000 characters; concise facts may be much shorter. Only topic summaries enter the main model context; the user-level `MEMORY.md` is still injected in full.

Automatic extraction defaults to no write. Every action needs a durable basis and an exact quote from a new visible user message. Prior conversation text helps resolve references but cannot supply new evidence. Original entry identities and a persisted session cursor prevent repeated extraction across runs and compaction. Long backlogs are evaluated chronologically within an 8,000-character input budget; later messages remain for subsequent runs. Oversized messages retain a persisted character offset and continue from that offset after restart; failed model or storage calls retain their input progress. Existing-topic input is capped at 24,000 characters. Replacements require complete old content, and uncertain new additions are suppressed when topic summaries are omitted.

Each stored source records `sessionId`, `recordedAt`, `via` (`auto` or `tool`), and optional `entryId`. Runtime code supplies identity. The memory tool carries its session identity through an in-process async context, not a public RPC parameter. Updates union sources; dream merges inherit the union of actual source topics. Legacy files retain absent provenance. `read` exposes frontmatter; the deferred `sessionRead` tool can page through visible user/assistant text in a source session, with the existing local-main and workspace boundary. Removed sessions can no longer be read.

Identical content and metadata do not refresh `updatedAt`; additional source evidence can persist without changing ranking. Replacements and dream rewrites can update stale names and descriptions. Dream still supports previews, reversible archive/restore, bounded retirement and conflict detection. Quiet workspaces become eligible for maintenance after 30 days even without five changed topics. Oversubscribed dream prompts reserve a rotating cold-topic share.

`packages/sidecar/tests/memory/admissionCases.ts` contains positive/negative semantic examples. Deterministic tests cover structural admission, fresh-evidence identity, source propagation, retries, budget boundaries and concurrent edits. These tests use model stubs; they do not measure real model precision. To evaluate prompt changes, run these examples against the configured extraction model and record unnecessary-write and missed-durable-fact rates separately. Require an exact supporting user quote and inspect whether the stored scope exceeds that quote.

Extraction logs report input size, elapsed time, candidate/admitted/rejected counts, writes, unchanged actions and provider usage when available; no conversation or evidence text is logged. Numeric expiry policies and a separate fact-confirmation timestamp are follow-up changes, rather than part of this implementation.
